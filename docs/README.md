## v3 で仕様を改定した箇所

handoff は v2.5 時点の仕様で、v3 で次の点が上書きされている。
両方が食い違うときは feedback 文書が勝つ。

| handoff の節 | v3 での扱い | 根拠 |
|---|---|---|
| §5.2 利用者画面のフロー・入力項目 | 5ステップ(おねがいカード3 + 当日のための詳細 + 確認)。「付き添いに関する補足」は「本人から一言」(公開・任意)に。手伝って欲しいことはチェック式 | feedback「v3のフォーム(5ステップ)」 |
| §5.5 「目的地は成立後も表示しない」 | 成立した担当サポーターにだけ、名前・待ち合わせ場所・行き先を `matchDetails` で表示する。募集中の公開は引き続き不可 | feedback「v3の設計モデル」 |
| §6 `needsPublic` のフィールド | `publicDistance`(選択式の移動距離)と `supportPoints`(固定語彙の id 配列)を追加。`publicArea` は利用者本人が書く丁目レベルの出発地・目的地 | feedback「判断の記録」 |
| §6 コレクション一覧 | `matchDetails/{matchingId}` を追加。成立時に管理者側で作る(§11 で求めている方式) | `src/lib/firestore.js` の `approveMatch` |
| 用語 | UI では「ニーズ」ではなく「おねがい」、アプリ名は「結び」 | AGENTS.md UX rules |

決定は日付つきで feedback/ か該当節に書く。書く基準は AGENTS.md と同じ:
3か月後の読者の調査時間を実際に節約する内容だけ。
